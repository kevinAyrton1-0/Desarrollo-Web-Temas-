21. PHP COMO API REST

Estructura basica api.php: 
header("Content-Type: application/json");
header("Access-Control-Allow-Origin: *");
header("Access-Control-Allow-Methods:
  GET,POST,PUT,DELETE");
header("Access-Control-Allow-Headers:
  Content-Type");

$method = $_SERVER["REQUEST_METHOD"];
$input = json_decode(
  file_get_contents("php://input"), true);

switch ($method) {
  case "GET":
    $rows = $pdo->query("SELECT * FROM items")
      ->fetchAll(PDO::FETCH_ASSOC);
    echo json_encode($rows);
    break;

  case "POST":
    $stmt = $pdo->prepare(
      "INSERT INTO items(nombre) VALUES(?)");
    $stmt->execute([$input["nombre"]]);
    echo json_encode([
      "id" => $pdo->lastInsertId()]);
    break;

  case "PUT":
    $stmt = $pdo->prepare(
      "UPDATE items SET nombre=? WHERE id=?");
    $stmt->execute([
      $input["nombre"], $input["id"]]);
    echo json_encode(["ok" => true]);
    break;

  case "DELETE":
    $stmt = $pdo->prepare(
      "DELETE FROM items WHERE id=?");
    $stmt->execute([$input["id"]]);
    echo json_encode(["ok" => true]);
    break;
}
Conexion PDO:

22. CORS — CROSS-ORIGIN

Que es CORS: Mecanismo de seguridad del navegador que bloquea peticiones a dominios diferentes al origen. Headers PHP necesarios:
Access-Control-Allow-Origin* o dominio especifico
Access-Control-Allow-MethodsGET, POST, PUT, DELETE
Access-Control-Allow-HeadersContent-Type, Authorization
Preflight (OPTIONS): 
if ($_SERVER["REQUEST_METHOD"]==="OPTIONS"){
  http_response_code(204);
  exit; // responder vacio al preflight
}
Mismo origen = OK: localhost:8080 → localhost:8080/api ✓
Diferente origen = CORS: localhost:3000 → localhost:8080/api ✗ (sin headers)

24. SPA, PWA Y HTMX

SPA (Single Page Application):
  • Una sola pagina HTML, JS controla la navegacion
  • Frameworks: React, Vue, Angular, Svelte
  • Router del lado cliente (no recarga pagina)
  • Ventaja: UX fluida; Desventaja: SEO complejo
PWA (Progressive Web App):
  • Web que se instala como app nativa
  • Requiere: manifest.json + Service Worker + HTTPS
  • Funciona offline con cache de Service Worker
// manifest.json (minimo)
{ "name": "Mi App",
  "short_name": "App",
  "start_url": "/",
  "display": "standalone",
  "icons": [{"src":"/icon.png",
    "sizes":"192x192","type":"image/png"}]
}

// Registrar Service Worker
navigator.serviceWorker.register("/sw.js");
HTMX (AJAX sin JS): 
<!-- GET al hacer click -->
<button hx-get="/api/items"
  hx-target="#lista">Cargar</button>

<!-- POST desde formulario -->
<form hx-post="/api/items"
  hx-target="#lista"
  hx-swap="beforeend">
  <input name="nombre">
  <button>Agregar</button>
</form>

<!-- DELETE con confirmacion -->
<button hx-delete="/api/items/5"
  hx-confirm="Seguro?"
  hx-target="closest li"
  hx-swap="outerHTML">X</button>
Atributos HTMX principales:
hx-get / hx-postPeticion GET / POST a URL
hx-put / hx-deletePeticion PUT / DELETE
hx-targetDonde insertar respuesta
hx-swapinnerHTML, outerHTML, beforeend...
hx-triggerEvento que dispara (click, submit...)
hx-confirmDialogo de confirmacion
