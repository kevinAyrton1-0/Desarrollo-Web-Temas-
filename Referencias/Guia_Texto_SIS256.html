TEMA 1: Conceptos Basicos de Internet y Web

1.1 Que es Internet

Internet es una red global de redes interconectadas que permite la comunicacion entre miles de millones de dispositivos en todo el mundo. No es controlada por una sola organizacion; funciona de manera descentralizada. En 2025, mas de 5.500 millones de personas (alrededor del 70% de la poblacion mundial) estan conectadas a Internet.

Internet no es una entidad unica, sino un conjunto de redes heterogeneas que se comunican entre si gracias a un conjunto comun de protocolos, principalmente TCP/IP. Estas redes incluyen desde las redes domesticas con Wi-Fi hasta los enormes centros de datos de empresas como Google o Amazon, pasando por las redes de universidades, gobiernos y operadores de telecomunicaciones.

Caracteristicas principales

  • Descentralizada: no existe un control unico ni un punto central de fallo
  • Global: conecta todos los continentes (incluyendo cables submarinos)
  • Basada en protocolos: TCP/IP como lenguaje comun de comunicacion
  • Interoperable: cualquier dispositivo puede conectarse si sigue los protocolos
  • Escalable: crece continuamente con nuevos dispositivos y redes

Servicios que ofrece Internet

Internet es la infraestructura sobre la cual funcionan multiples servicios:

  • World Wide Web (WWW): paginas web accesibles a traves de navegadores
  • Correo electronico (Email): Gmail, Outlook, etc.
  • Mensajeria y videollamadas: WhatsApp, Zoom, Microsoft Teams
  • Streaming: YouTube, Netflix, Spotify
  • Comercio electronico: Amazon, MercadoLibre
  • Redes sociales: Instagram, TikTok, Facebook
  • Transferencia de archivos (FTP): subir/descargar archivos a servidores

1.2 Historia y Evolucion de Internet

Internet no nacio de un dia para otro; es el resultado de decadas de investigacion y desarrollo:

Linea de tiempo

  • 1969 — ARPANET: la primera red, conectando 4 computadoras de universidades de EE.UU. Financiada por el Departamento de Defensa (DARPA).
  • 1971 — Email: Ray Tomlinson envia el primer correo electronico, usando el simbolo @ para separar usuario y dominio.
  • 1983 — TCP/IP: se adopta como protocolo estandar, permitiendo que redes diferentes se comuniquen entre si. Este momento marca el nacimiento real de «Internet».
  • 1989 — WWW: Tim Berners-Lee, en el CERN (Suiza), propone un sistema de hipertexto que se convertiria en la World Wide Web.
  • 1993 — Mosaic: el primer navegador grafico popular, que democratiza el acceso a la web.
  • 1995-2000 — Burbuja .com: explosion del comercio electronico. Nacen Amazon, eBay, Google. Muchas startups fallan pero las sobrevivientes transforman el mundo.
  • 2004 — Web 2.0: contenido generado por usuarios. Facebook, YouTube, blogs, wikis.
  • 2007 — Smartphones: el iPhone populariza Internet movil, cambiando como consumimos contenido.
  • 2010+ — Cloud y Apps: servicios en la nube (AWS, Google Cloud), apps moviles, IoT.
  • 2020 — Pandemia: aceleracion digital masiva. Teletrabajo, educacion online, telemedicina.
  • 2023+ — IA generativa: ChatGPT y la inteligencia artificial transforman la web y el desarrollo de software.

  • Web 2.0 (2004-2020): la web interactiva. Los usuarios pueden crear contenido (blogs, redes sociales, YouTube). AJAX permite interacciones sin recargar la pagina.
  • Web 3.0 (2020+): la web semantica e inteligente. Inteligencia artificial, personalizacion, descentralizacion (blockchain), busqueda inteligente.

1.3 Modelo Cliente / Servidor

El modelo Cliente/Servidor es la arquitectura fundamental sobre la que funciona la web. Describe como dos tipos de programas se comunican a traves de la red:

  • Cliente: el programa que realiza peticiones. En la web, el cliente tipico es el navegador (Chrome, Firefox, Safari). El cliente envia peticiones al servidor y muestra los resultados al usuario.
  • Servidor: el programa que espera y responde peticiones. Ejecuta software como Apache, Nginx o Node.js. Procesa la solicitud, puede consultar bases de datos, y devuelve una respuesta (generalmente HTML, JSON o archivos).

Flujo tipico

  1. El usuario escribe una URL en el navegador (o hace clic en un enlace).
  2. El navegador (cliente) envia una peticion HTTP al servidor.
  3. El servidor recibe la peticion, la procesa (puede ejecutar PHP, consultar MySQL, etc.).
  4. El servidor genera una respuesta HTTP con el contenido (HTML, CSS, JS, imagenes).
  5. El navegador recibe la respuesta y renderiza (muestra) la pagina al usuario.

Este proceso se repite cada vez que el usuario navega a una nueva pagina o interactua con la web. En aplicaciones modernas con AJAX, el navegador puede hacer peticiones adicionales sin recargar la pagina completa.

1.4 Protocolos de Red: TCP/IP

TCP/IP (Transmission Control Protocol / Internet Protocol) es el conjunto de protocolos que permite la comunicacion en Internet. Todo dispositivo conectado a Internet usa TCP/IP para enviar y recibir datos.

Capas del modelo TCP/IP

CapaFuncionProtocolos
AplicacionProtocolos que usa el usuario finalHTTP, HTTPS, FTP, SMTP, DNS
TransporteDivide datos en paquetes y asegura entregaTCP (confiable), UDP (rapido)
InternetDireccionamiento y enrutamientoIP (IPv4, IPv6)
Acceso a RedTransmision fisica de datosEthernet, Wi-Fi, fibra optica

TCP garantiza que los datos lleguen completos y en orden (usado para web, email). UDP es mas rapido pero no garantiza la entrega (usado para streaming, videollamadas, juegos online). IP asigna una direccion unica a cada dispositivo: las direcciones IPv4 (como 192.168.1.1) se estan agotando, por lo que se esta migrando a IPv6 (como 2001:0db8:85a3::8a2e:0370:7334).

Intranet y Extranet

Intranet: red privada interna de una organizacion que usa los mismos protocolos de Internet (HTTP, TCP/IP) pero no esta conectada al exterior. Solo pueden acceder empleados de la organizacion. Ejemplo: portal interno con documentos, directorio de empleados.

Extranet: extension de la intranet que permite acceso controlado a usuarios externos (clientes, proveedores) a traves de Internet de forma segura (VPN/HTTPS). Ejemplo: portal de proveedores para seguimiento de pedidos.

Internet: red publica global, accesible para cualquier persona sin restricciones de acceso al contenido publico.

1.6 World Wide Web (WWW)

La World Wide Web (WWW o simplemente «la web») es un sistema de informacion de hipertexto que funciona sobre Internet. Fue creada en 1989 por Tim Berners-Lee en el CERN (Laboratorio Europeo de Fisica de Particulas, Suiza).

Importante: WWW ≠ Internet. Internet es la red fisica global. La WWW es solo uno de los muchos servicios que funcionan sobre Internet (otros son email, FTP, DNS, etc.).

Los tres pilares de la Web

  1. HTML (HyperText Markup Language): lenguaje de marcado para estructurar el contenido de las paginas web.
  2. URL (Uniform Resource Locator): direccion unica que identifica cada recurso en la web.
  3. HTTP (HyperText Transfer Protocol): protocolo que define como se comunican el cliente y el servidor.

La web funciona asi: el usuario escribe una URL en el navegador, que envia una peticion HTTP al servidor correspondiente. El servidor responde con un documento HTML que el navegador interpreta y muestra visualmente al usuario. Los enlaces (hipervinculos) dentro de las paginas permiten navegar a otros documentos, creando la «telarana» de informacion que da nombre a la World Wide Web.

1.7 HTML: Introduccion al Lenguaje de la Web

HTML (HyperText Markup Language) es el lenguaje estandar utilizado para crear y estructurar el contenido de las paginas web. No es un lenguaje de programacion; es un lenguaje de marcado que usa etiquetas para organizar texto, imagenes, enlaces y multimedia.

Estructura basica de un documento HTML

<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>Mi primera pagina</title>
</head>
<body>
    <h1>Hola Mundo</h1>
    <p>Este es mi primer parrafo.</p>
    <a href="https://www.usfx.bo">Enlace a USFX</a>
</body>
</html>

Versiones de HTML

HTML ha evolucionado desde su creacion: HTML 1.0 (1991), HTML 2.0 (1995), HTML 3.2 (1997), HTML 4.01 (1999), XHTML (2000), hasta llegar a HTML5 (2014), que es el estandar actual. Hoy se usa el HTML5 Living Standard, mantenido por el grupo WHATWG, que se actualiza continuamente sin numeros de version.

HTML5 introdujo etiquetas semanticas (<header>, <nav>, <main>, <section>, <article>, <footer>), soporte nativo para <video> y <audio> (eliminando la necesidad de Flash), nuevos tipos de input para formularios (email, date, range), y multiples APIs de JavaScript (Geolocation, localStorage, Canvas, Drag & Drop).

1.9 HTTP y HTTPS

HTTP (HyperText Transfer Protocol) es el protocolo de comunicacion que define como el navegador (cliente) solicita recursos y como el servidor responde. Es un protocolo sin estado: cada peticion es independiente, el servidor no recuerda peticiones anteriores (para mantener estado se usan cookies y sesiones).

Peticion HTTP (Request)

Cada peticion incluye: un metodo (GET, POST, PUT, DELETE...), la URL del recurso, headers (cabeceras con informacion adicional) y opcionalmente un body (datos enviados al servidor).

GET /index.html HTTP/1.1
Host: www.ejemplo.com
Accept: text/html

Respuesta HTTP (Response)

El servidor responde con: un codigo de estado (200, 404, 500...), headers de respuesta y el body con el contenido.

HTTP/1.1 200 OK
Content-Type: text/html

<html>...</html>

Metodos HTTP

MetodoUsoEjemplo
GETObtener/leer un recursoCargar una pagina web
POSTCrear un nuevo recursoEnviar un formulario
PUTActualizar/reemplazarEditar un perfil
PATCHActualizar parcialmenteCambiar solo el email
DELETEEliminar un recursoBorrar un registro

En formularios HTML solo se pueden usar GET (datos visibles en la URL) y POST (datos en el body, no visibles). Los demas metodos se usan con JavaScript (Fetch/AJAX) y APIs REST.

Codigos de estado HTTP

RangoCategoriaEjemplos comunes

Versiones de HTTP

HTTP/1.0 (1996): una conexion por recurso. HTTP/1.1 (1999): conexiones persistentes, la version mas usada por anos. HTTP/2 (2015): multiplexacion, compresion de headers, mucho mas rapido. HTTP/3 (2022): basado en QUIC/UDP, menor latencia, adoptado por Google y Facebook.

HTTPS: HTTP Seguro

HTTPS = HTTP + TLS (cifrado). Toda la comunicacion entre navegador y servidor se cifra usando certificados SSL/TLS. El candado en la barra de direcciones indica una conexion segura. Hoy es obligatorio para cualquier sitio web profesional: Google lo exige para buen posicionamiento (SEO), y los navegadores marcan los sitios HTTP como «No seguro». Los certificados se pueden obtener gratis con Let's Encrypt.

DNS: Sistema de Nombres de Dominio

El DNS (Domain Name System) traduce nombres de dominio legibles (como www.google.com) a direcciones IP numericas (como 142.250.80.46). Sin DNS, tendriamos que memorizar numeros para visitar cada sitio web.

La jerarquia de dominios va de derecha a izquierda: TLD (.com, .org, .bo), dominio (google, usfx), subdominio (www, mail, api). Ejemplo: www.usfx.bo = subdominio.dominio.TLD.

Un navegador web es la aplicacion que interpreta el codigo HTML, CSS y JavaScript para mostrar las paginas web al usuario. Los principales navegadores en 2025:

1.11 Frontend vs Backend

El desarrollo web se divide en dos grandes areas:

Frontend (Lado del Cliente)

Todo lo que el usuario ve e interactua directamente en el navegador:

  • HTML: estructura y contenido
  • CSS: diseno, colores, tipografia, layout
  • JavaScript: interactividad, animaciones, logica del cliente
  • Frameworks frontend: React, Vue, Angular, Svelte

Backend (Lado del Servidor)

Todo lo que ocurre en el servidor, oculto para el usuario:

  • Lenguajes: PHP, Python, Java, Node.js, C#, Go, Ruby
  • Bases de datos: MySQL, PostgreSQL, MongoDB, SQLite
  • Logica de negocio: autenticacion, validacion, procesamiento
  • Frameworks backend: Laravel (PHP), Django (Python), Express (Node.js), Spring (Java)
  • APIs: REST, GraphQL

Un desarrollador Full-Stack maneja tanto frontend como backend. En esta materia (SIS 256) cubrimos ambos lados: HTML/CSS y JavaScript para el frontend, PHP y MySQL para el backend.

Stacks de desarrollo

Un «stack» es el conjunto de tecnologias usadas juntas:

  • LAMP: Linux + Apache + MySQL + PHP (lo que usamos con XAMPP en Windows)
  • MERN: MongoDB + Express.js + React + Node.js (full JavaScript)
  • MEAN: MongoDB + Express.js + Angular + Node.js
  • JAMstack: JavaScript + APIs + Markup (sitios estaticos modernos)

1.12 Herramientas y Entorno de Desarrollo

XAMPP: nuestro entorno local

XAMPP es un paquete gratuito que instala un servidor web completo en tu computadora: X (cross-platform) + Apache + MySQL/MariaDB + PHP + Perl. Permite desarrollar y probar aplicaciones web localmente sin necesitar un servidor en Internet.

El flujo de trabajo con XAMPP es: 1) Iniciar Apache y MySQL, 2) Colocar archivos en la carpeta htdocs/, 3) Abrir localhost en el navegador, 4) Ver el resultado.

Herramientas del Desarrollador (DevTools)

Todos los navegadores modernos incluyen DevTools (accesibles con F12 o Ctrl+Shift+I):

  • Elements: inspeccionar y modificar HTML/CSS en tiempo real
  • Console: ejecutar JavaScript, ver errores y mensajes de log
  • Network: ver todas las peticiones HTTP (headers, tiempos, datos)
  • Sources: depurar JavaScript con breakpoints
  • Application: cookies, localStorage, Service Workers

Hosting y dominios

Para publicar un sitio web en Internet se necesita:

  1. Registrar un dominio (ej: misitio.com) — ~$10-15/ano
  2. Contratar hosting (o usar gratuito: GitHub Pages, Netlify, Vercel)
  3. Subir los archivos (HTML, CSS, JS, PHP) al servidor
  4. Configurar DNS para que el dominio apunte al hosting

Los tipos de hosting incluyen: compartido (varios sitios por servidor, economico), VPS (servidor virtual privado), dedicado (servidor exclusivo), y cloud (AWS, Google Cloud, Azure).

Seguridad web basica

  • HTTPS obligatorio: siempre usar certificado SSL/TLS (Let's Encrypt es gratuito)
  • Validar entradas: NUNCA confiar en datos del usuario. Validar tanto en frontend como en backend.
  • Contrasenas seguras: minimo 12 caracteres, nunca guardar en texto plano (usar bcrypt o Argon2).
  • Mantener software actualizado: parches de seguridad para servidor, PHP, frameworks.

Regla de oro: nunca confiar en datos que vienen del cliente. Todo se puede manipular con DevTools.

TEMA 2: Lenguajes de Marcas HTML, XML y Tecnologia Asociada

2.1 Que es HTML

HTML son las siglas de HyperText Markup Language (Lenguaje de Marcado de Hipertexto). Es el lenguaje estandar utilizado para crear y estructurar el contenido de las paginas web. A diferencia de los lenguajes de programacion como Python o Java, HTML no es un lenguaje de programacion propiamente dicho: es un lenguaje de marcado. Esto significa que su funcion principal es definir la estructura y el significado del contenido mediante etiquetas (tags) que rodean el texto y otros elementos, indicandole al navegador como debe interpretarlos y mostrarlos.

El termino hipertexto se refiere a la capacidad de enlazar documentos entre si mediante hipervinculos. Cuando hacemos clic en un enlace y navegamos a otra pagina, estamos utilizando la funcionalidad de hipertexto que define a HTML. El termino marcado proviene de la practica editorial tradicional de marcar manuscritos con instrucciones para el impresor. De manera similar, las etiquetas HTML son instrucciones que le dicen al navegador que hacer con cada fragmento de contenido: si es un titulo, un parrafo, una imagen, un enlace, etc.

Historia de HTML

Los origenes de HTML se remontan a SGML (Standard Generalized Markup Language), un estandar internacional para la definicion de lenguajes de marcado publicado en 1986 (ISO 8879). SGML proporcionaba un marco general para crear lenguajes de marcado especificos, y HTML nacio como una aplicacion simplificada de SGML orientada a la web.

En 1989, Tim Berners-Lee, un cientifico britanico que trabajaba en el CERN (Organizacion Europea para la Investigacion Nuclear) en Ginebra, propuso un sistema de gestion de informacion basado en hipertexto. En 1990, junto con Robert Cailliau, formalizaron esta propuesta y crearon el primer navegador web y el primer servidor web. Berners-Lee escribio la primera version de HTML, que incluia apenas 18 etiquetas, muchas de las cuales todavia se usan hoy en dia.

La evolucion del estandar HTML ha pasado por varias versiones importantes:

VersionAnioDescripcion

HTML 3.01995Propuesta ambiciosa que nunca se implemento completamente por ser demasiado compleja.

HTML5 fue desarrollado conjuntamente por el W3C y el WHATWG (Web Hypertext Application Technology Working Group). A diferencia de las versiones anteriores, HTML5 se considera un estandar vivo (living standard) que se actualiza continuamente sin necesidad de publicar nuevas versiones numeradas.

2.2 Estructura de un Documento HTML

Todo documento HTML sigue una estructura jerarquica bien definida. Al igual que un libro tiene portada, indice y capitulos, un documento HTML tiene una declaracion de tipo, un encabezado y un cuerpo. Comprender esta estructura es fundamental para escribir codigo HTML correcto y que los navegadores puedan interpretar sin ambiguedades.

La estructura basica de cualquier pagina HTML5 es la siguiente:

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Mi Pagina Web</title>
</head>
<body>
    <!-- Aqui va el contenido visible -->
    <h1>Hola Mundo</h1>
    <p>Este es mi primer parrafo.</p>
</body>
</html>

Declaracion DOCTYPE

La primera linea de todo documento HTML5 debe ser <!DOCTYPE html>. Esta declaracion no es una etiqueta HTML propiamente dicha, sino una instruccion para el navegador que le indica que version de HTML se esta utilizando. En HTML5, la declaracion es extremadamente simple comparada con versiones anteriores (en HTML 4.01, el DOCTYPE requeria una larga referencia a una DTD). El DOCTYPE asegura que el navegador renderice la pagina en modo estandar y no en modo quirks (un modo de compatibilidad que emula comportamientos antiguos).

Elemento <html>

El elemento <html> es el elemento raiz de todo documento HTML. Todos los demas elementos deben estar contenidos dentro de el. El atributo lang="es" indica el idioma del documento, lo cual es importante para los lectores de pantalla, los motores de busqueda y las herramientas de traduccion automatica.

Elemento <head>

El elemento <head> contiene metadatos sobre el documento: informacion que no se muestra directamente en la pagina pero que es esencial para su correcto funcionamiento. Los elementos que pueden ir dentro del head son:

  • <title> — Define el titulo que aparece en la pestania del navegador y en los resultados de busqueda. Cada pagina debe tener un titulo unico y descriptivo.
  • <meta charset="UTF-8"> — Especifica la codificacion de caracteres. UTF-8 soporta practicamente todos los caracteres del mundo, incluyendo tildes y la enie.
  • <meta name="viewport"> — Esencial para diseno responsive. Indica al navegador movil que el ancho de la pagina debe adaptarse al ancho del dispositivo.
  • <meta name="author"> — Indica el autor del documento.
  • <meta name="description"> — Proporciona una descripcion breve de la pagina, usada por los motores de busqueda para mostrar en los resultados.
  • <meta name="keywords"> — Lista de palabras clave separadas por comas (su importancia para SEO ha disminuido, pero aun se usa).
  • <link> — Enlaza recursos externos como hojas de estilo CSS o iconos favicon.
  • <style> — Permite incluir estilos CSS directamente en el documento.
  • <script> — Permite incluir o enlazar codigo JavaScript.

    <meta charset="UTF-8">

Elemento <body>

El elemento <body> contiene todo el contenido visible de la pagina: textos, imagenes, enlaces, formularios, tablas, etc. Todo lo que el usuario ve e interactua se encuentra dentro de este elemento. Solo puede haber un <body> por documento.

2.3 Elementos HTML

Los elementos HTML son los bloques de construccion fundamentales de una pagina web. Cada elemento se define mediante una etiqueta de apertura, contenido y una etiqueta de cierre. Por ejemplo, <p>Hola</p> define un parrafo con el texto "Hola". Algunos elementos, como <img> o <br>, son vacios y no tienen etiqueta de cierre.

Elementos de bloque vs. elementos en linea

Los elementos de bloque (block-level elements) ocupan todo el ancho disponible de su contenedor y siempre comienzan en una nueva linea. Ejemplos: <div>, <p>, <h1> a <h6>, <ul>, <table>, <form>. Los elementos en linea (inline elements) solo ocupan el espacio necesario para su contenido y no fuerzan un salto de linea. Ejemplos: <span>, <a>, <strong>, <em>, <img>, <code>.

Esta distincion es crucial para entender la maquetacion. Un <div> ocupa una linea completa aunque su contenido sea corto, mientras que un <span> fluye junto al texto circundante. En CSS moderno, se puede cambiar este comportamiento con la propiedad display.

Encabezados y parrafos

HTML proporciona seis niveles de encabezados, de <h1> (el mas importante) a <h6> (el menos importante). Los encabezados deben usarse de forma jerarquica para estructurar el contenido, no simplemente para hacer texto mas grande. Los motores de busqueda usan los encabezados para entender la estructura de la pagina. El elemento <p> define un parrafo de texto.

<h1>Titulo principal de la pagina</h1>
<h2>Subtitulo de seccion</h2>
<p>Este es un parrafo de texto dentro de la seccion.</p>
<h3>Sub-subtitulo</h3>
<p>Otro parrafo con mas detalle.</p>

Contenedores: div y span

El elemento <div> es un contenedor generico de bloque que se usa para agrupar elementos y aplicarles estilos o comportamientos comunes. El elemento <span> es su equivalente en linea: permite envolver una porcion de texto para aplicarle estilos sin romper el flujo del parrafo. Ambos son elementos sin significado semantico propio; su proposito es puramente estructural y de presentacion.

Listas

HTML ofrece tres tipos de listas. Las listas ordenadas (<ol>) muestran elementos numerados. Las listas no ordenadas (<ul>) muestran elementos con vinietas. Ambas usan <li> para cada elemento. Las listas de definicion (<dl>) contienen pares termino-definicion, usando <dt> para el termino y <dd> para la definicion.

<!-- Lista ordenada -->
<ol>
    <li>Primer paso</li>
    <li>Segundo paso</li>
    <li>Tercer paso</li>
</ol>

<!-- Lista no ordenada -->
<ul>
    <li>HTML</li>
    <li>CSS</li>
    <li>JavaScript</li>
</ul>

<!-- Lista de definicion -->
<dl>
    <dt>HTML</dt>
    <dd>Lenguaje de marcado para crear paginas web.</dd>
    <dt>CSS</dt>
    <dd>Lenguaje para dar estilo a documentos HTML.</dd>
</dl>

Tablas

Las tablas en HTML se crean con el elemento <table>. Cada fila se define con <tr> (table row), cada celda de datos con <td> (table data) y cada celda de encabezado con <th> (table header). Para mayor organizacion semantica, se pueden usar <thead> para agrupar las filas de encabezado y <tbody> para las filas de datos.

Los atributos colspan y rowspan permiten que una celda ocupe varias columnas o varias filas respectivamente. Esto es util para crear encabezados que abarcan multiples columnas o celdas que combinan filas.

<table>
    <thead>
        <tr>
            <th>Nombre</th>
            <th>Edad</th>
            <th>Ciudad</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>Maria</td>
            <td>22</td>
            <td>Sucre</td>
        </tr>
        <tr>
            <td colspan="2">Celda combinada</td>
            <td>La Paz</td>
        </tr>
    </tbody>
</table>
Importante: Las tablas deben usarse exclusivamente para datos tabulares, nunca para maquetar la pagina. Para la maquetacion se deben usar CSS Flexbox o CSS Grid.

2.4 Formularios HTML

Los formularios son el mecanismo principal mediante el cual los usuarios envian informacion a un servidor web. Desde un simple campo de busqueda hasta un complejo formulario de registro, los formularios HTML permiten recoger datos del usuario y procesarlos en el servidor. Sin formularios, la web seria un medio puramente informativo sin capacidad de interaccion.

El elemento <form> es el contenedor de todos los campos de un formulario. Tiene dos atributos fundamentales: action que especifica la URL del script del servidor que procesara los datos, y method que define el metodo HTTP para enviar los datos.

GET vs POST

El metodo GET envia los datos del formulario como parametros en la URL (visible en la barra de direcciones). Es adecuado para busquedas y consultas donde los datos no son sensibles, ya que la URL puede ser guardada como marcador o compartida. Tiene un limite de longitud (aproximadamente 2048 caracteres). El metodo POST envia los datos en el cuerpo de la solicitud HTTP, de manera que no son visibles en la URL. Es el metodo recomendado para enviar datos sensibles (contrasenas), grandes cantidades de datos, o cuando la accion modifica el estado del servidor (crear, actualizar o eliminar registros).

Tipos de input

<form action="procesar.php" method="POST">

    <!-- Campo de texto -->
    <label for="nombre">Nombre:</label>
    <input type="text" id="nombre" name="nombre" required>

    <!-- Contrasena -->
    <input type="password" name="clave">

    <!-- Email -->
    <input type="email" name="correo">

    <!-- Numero -->
    <input type="number" name="edad" min="1" max="120">

    <!-- Fecha -->
    <input type="date" name="nacimiento">

    <!-- Radio buttons (solo uno puede seleccionarse) -->
    <input type="radio" name="genero" value="M"> Masculino
    <input type="radio" name="genero" value="F"> Femenino

    <!-- Checkbox (multiples pueden seleccionarse) -->
    <input type="checkbox" name="materias[]" value="html"> HTML
    <input type="checkbox" name="materias[]" value="php"> PHP

    <!-- Campo oculto -->
    <input type="hidden" name="accion" value="registrar">

    <!-- Lista desplegable -->
    <select name="departamento">
        <option value="">Seleccione...</option>
        <option value="CHQ">Chuquisaca</option>
        <option value="LPZ">La Paz</option>
        <option value="CBB">Cochabamba</option>
    </select>

    <!-- Area de texto -->
    <textarea name="comentario" rows="5" cols="40"></textarea>

    <!-- Boton de envio -->
    <button type="submit">Enviar</button>

</form>

El atributo name es fundamental en cada campo del formulario: es el nombre de la variable que recibira el servidor. Sin el atributo name, los datos de ese campo no seran enviados. El atributo required indica que el campo es obligatorio y el navegador no permitira enviar el formulario si esta vacio. El elemento <label> asocia un texto descriptivo con un campo del formulario mediante el atributo for, mejorando la accesibilidad.

2.5 Hipervinculos e Imagenes

Los hipervinculos son la esencia de la web: son el mecanismo que permite navegar de una pagina a otra, creando la red interconectada de documentos que conocemos como World Wide Web. Sin enlaces, cada pagina seria una isla aislada. El elemento <a> (anchor) crea hipervinculos.

<!-- Enlace basico -->
<a href="https://www.usfx.bo">Visitar USFX</a>

<!-- Abrir en nueva pestana -->
<a href="contacto.html" target="_blank">Contacto</a>

<!-- Enlace a seccion interna -->
<a href="#seccion2">Ir a seccion 2</a>

<!-- Enlace de correo -->
<a href="mailto:info@ejemplo.com">Enviar correo</a>

Rutas absolutas vs. relativas

Una ruta absoluta incluye la URL completa, incluyendo el protocolo: https://www.ejemplo.com/pagina.html. Se usa para enlazar a sitios web externos. Una ruta relativa indica la ubicacion de un archivo en relacion a la ubicacion del documento actual: imagenes/foto.jpg busca un archivo en la subcarpeta "imagenes" del directorio actual. ../otro.html sube un nivel en la jerarquia de directorios. Las rutas relativas son preferibles para recursos dentro del mismo sitio web porque son mas portables.

Imagenes

El elemento <img> inserta una imagen en la pagina. Es un elemento vacio (no tiene etiqueta de cierre). Sus atributos principales son src (la ruta de la imagen) y alt (texto alternativo que se muestra si la imagen no puede cargarse y que es leido por los lectores de pantalla).

<img src="imagenes/logo.png" alt="Logo de la empresa" width="200">

Video y Audio

HTML5 introdujo elementos nativos para multimedia, eliminando la necesidad de plugins como Flash. El elemento <video> permite reproducir video y <audio> permite reproducir audio directamente en el navegador.

<video src="video.mp4" controls width="640">
    Tu navegador no soporta video HTML5.
</video>

<audio src="musica.mp3" controls>
    Tu navegador no soporta audio HTML5.
</audio>

2.6 Elementos Semanticos HTML5

Antes de HTML5, la mayoria de la estructura de una pagina se creaba con elementos <div> genericos, utilizando clases como "header", "nav" o "footer" para indicar su proposito. HTML5 introdujo un conjunto de elementos semanticos que describen claramente su funcion, tanto para los desarrolladores como para los navegadores, motores de busqueda y tecnologias de asistencia.

El HTML semantico es importante por varias razones. Primero, mejora la accesibilidad: los lectores de pantalla pueden identificar las diferentes secciones de la pagina y permitir al usuario navegar directamente al contenido principal, la navegacion o el pie de pagina. Segundo, mejora el SEO (optimizacion para motores de busqueda): Google y otros buscadores entienden mejor la estructura de la pagina cuando se usan elementos semanticos. Tercero, mejora la mantenibilidad del codigo: leer <nav> es mucho mas claro que leer <div class="nav">.

<body>
    <header>
        <h1>Mi Sitio Web</h1>
        <nav>
            <a href="/">Inicio</a>
            <a href="/servicios">Servicios</a>
            <a href="/contacto">Contacto</a>
        </nav>
    </header>

    <main>
        <section>
            <h2>Noticias</h2>
            <article>
                <h3>Titulo del articulo</h3>
                <p>Contenido del articulo...</p>
                <figure>
                    <img src="foto.jpg" alt="Descripcion">
                    <figcaption>Pie de foto explicativo</figcaption>
                </figure>
            </article>
        </section>

        <aside>
            <h3>Barra lateral</h3>
            <p>Contenido complementario...</p>
        </aside>
    </main>

    <footer>
        <p>&copy; 2026 Mi Sitio Web</p>
    </footer>
</body>
ElementoProposito
<header>Encabezado de la pagina o de una seccion. Puede contener logo, titulo y navegacion.
<nav>Seccion de enlaces de navegacion principal.
<main>Contenido principal y unico de la pagina. Solo debe haber uno por documento.
<section>Seccion tematica del contenido, generalmente con su propio encabezado.
<article>Contenido independiente y autocontenido (una noticia, un post de blog).
<aside>Contenido tangencialmente relacionado (barra lateral, notas al margen).
<footer>Pie de pagina. Contiene informacion de copyright, enlaces legales, etc.
<figure>Contenido autonomo como imagenes, diagramas o fragmentos de codigo.
<figcaption>Leyenda o pie de un elemento <figure>.

2.7 CSS - Hojas de Estilo en Cascada

CSS (Cascading Style Sheets, Hojas de Estilo en Cascada) es el lenguaje utilizado para definir la presentacion visual de los documentos HTML. Mientras HTML se encarga de la estructura y el contenido, CSS controla como se ve: colores, tipografias, espaciados, maquetacion, animaciones y mas. Esta separacion entre contenido (HTML) y presentacion (CSS) es un principio fundamental del desarrollo web moderno.

Las ventajas de separar HTML y CSS son multiples: se puede cambiar completamente la apariencia de un sitio web sin tocar el HTML; multiples paginas pueden compartir la misma hoja de estilos, garantizando consistencia visual; los archivos HTML son mas ligeros y faciles de mantener; y diferentes hojas de estilo pueden aplicarse para diferentes dispositivos (pantalla, impresion, movil).

Tres formas de incluir CSS

1. CSS en linea (inline): Se aplica directamente en un elemento HTML mediante el atributo style. Solo afecta a ese elemento especifico. No es recomendable porque mezcla contenido con presentacion y es dificil de mantener.

<p style="color: red; font-size: 18px;">Texto rojo</p>

2. CSS embebido (interno): Se coloca dentro de un elemento <style> en el <head> del documento. Afecta solo a esa pagina. Util para estilos especificos de una sola pagina.

<head>
    <style>
        p {
            color: blue;
            font-size: 16px;
        }
    </style>
</head>

3. CSS externo: Se escribe en un archivo separado con extension .css y se enlaza al HTML con el elemento <link>. Es la forma recomendada porque permite reutilizar los estilos en multiples paginas y mantiene una clara separacion de responsabilidades.

<link rel="stylesheet" href="estilos.css">

Selectores CSS

Los selectores CSS determinan a que elementos HTML se aplican las reglas de estilo. Los tres selectores fundamentales son:

/* Selector de elemento: selecciona todos los <p> */
p {
    color: #333;
}

/* Selector de clase (.): selecciona elementos con class="destacado" */
.destacado {
    background-color: yellow;
    font-weight: bold;
}

/* Selector de ID (#): selecciona el elemento con id="titulo" */
#titulo {
    font-size: 2rem;
    text-align: center;
}

Una clase (con punto) puede aplicarse a multiples elementos y un elemento puede tener varias clases. Un ID (con numeral) debe ser unico en toda la pagina; solo un elemento puede tener un ID especifico. La especificidad de CSS determina cual estilo prevalece cuando hay conflictos: los estilos inline tienen la mayor prioridad, seguidos por ID, luego clases, y finalmente selectores de elemento.

El modelo de caja (Box Model)

Todo elemento HTML es tratado por CSS como una caja rectangular. El modelo de caja describe como se compone el espacio total que ocupa un elemento, y tiene cuatro capas (de adentro hacia afuera):

  • Content (contenido): El area donde se muestra el texto, imagen u otro contenido del elemento.
  • Padding (relleno): Espacio transparente entre el contenido y el borde. Aumenta el area interna del elemento.
  • Border (borde): El borde visible que rodea el padding y el contenido.
  • Margin (margen): Espacio transparente fuera del borde. Separa al elemento de otros elementos vecinos.
.caja {
    width: 300px;          /* ancho del contenido */
    padding: 20px;         /* relleno interno */
    border: 2px solid #333; /* borde */
    margin: 15px;          /* margen externo */

    /* Ancho total = 300 + 20*2 + 2*2 + 15*2 = 374px */
    /* Con box-sizing: border-box, el width incluye padding y border */
    box-sizing: border-box; /* Recomendado: width = 300px total */
}
Consejo: Se recomienda aplicar box-sizing: border-box a todos los elementos con el selector universal * { box-sizing: border-box; }. Esto hace que el width y height incluyan el padding y el borde, facilitando el calculo de dimensiones.

2.8 Propiedades CSS Importantes

CSS cuenta con cientos de propiedades, pero un conjunto relativamente pequeno cubre la gran mayoria de las necesidades de estilizado. A continuacion se describen las propiedades mas utilizadas organizadas por categoria.

Color y fondo

.elemento {
    color: #2C3E50;             /* color del texto (hexadecimal) */
    color: rgb(44, 62, 80);     /* lo mismo en formato RGB */
    background-color: #ecf0f1; /* color de fondo */
}

Tipografia

.texto {
    font-family: 'Segoe UI', Arial, sans-serif; /* familia tipografica */
    font-size: 16px;           /* tamano de fuente */
    font-weight: bold;         /* grosor: normal, bold, 100-900 */
    font-style: italic;        /* estilo: normal, italic */
    text-align: center;        /* alineacion: left, center, right, justify */
    text-decoration: underline; /* decoracion: none, underline, line-through */
    line-height: 1.6;          /* interlineado */
}

Dimensiones y bordes

.caja {
    width: 80%;              /* ancho (px, %, em, rem, vw) */
    max-width: 600px;        /* ancho maximo */
    height: auto;             /* alto automatico segun contenido */
    border: 1px solid #ccc;  /* borde: grosor estilo color */
    border-radius: 8px;      /* esquinas redondeadas */
    padding: 20px;            /* relleno igual en los 4 lados */
    padding: 10px 20px;       /* vertical horizontal */
    margin: 10px 20px 10px 20px; /* arriba derecha abajo izquierda */
}

La propiedad display

La propiedad display controla como un elemento se comporta en el flujo del documento. Los valores mas comunes son:

ValorComportamiento

2.9 Maquetacion CSS

La maquetacion (layout) se refiere a como se organizan y posicionan los elementos en la pagina. CSS proporciona varias herramientas para controlar el posicionamiento de los elementos.

Propiedad position

La propiedad position permite sacar elementos del flujo normal del documento y colocarlos en posiciones especificas. Una vez establecido el tipo de posicionamiento, se usan las propiedades top, right, bottom y left para especificar la ubicacion.

ValorDescripcion
staticValor por defecto. El elemento sigue el flujo normal. Las propiedades top/right/bottom/left no tienen efecto.
relativeEl elemento se posiciona relativo a su posicion normal. Se puede mover con top/left, pero su espacio original se preserva.
absoluteEl elemento se saca del flujo y se posiciona relativo a su ancestro posicionado mas cercano (no static). Si no hay ninguno, se posiciona relativo al <html>.
fixedComo absolute, pero relativo a la ventana del navegador. No se mueve al hacer scroll. Ideal para barras de navegacion fijas.
/* Barra de navegacion fija en la parte superior */
.navbar {
    position: fixed;
    top: 0;
    left: 0;
    width: 100%;
    background: #2C3E50;
    z-index: 1000;
}

/* Elemento posicionado dentro de su contenedor */
.contenedor {
    position: relative;  /* establece contexto de posicionamiento */
}
.badge {
    position: absolute;
    top: -10px;
    right: -10px;
}

Centrar elementos

Para centrar horizontalmente un elemento de bloque con ancho definido, se usa margin: 0 auto. Para centrar texto, se usa text-align: center en el contenedor. Para centrar vertical y horizontalmente, Flexbox es la solucion mas elegante (ver siguiente seccion).

/* Centrar un div horizontalmente */
.centrado {
    width: 600px;
    margin: 0 auto;  /* margen automatico a izquierda y derecha */
}

2.10 Flexbox

Flexbox (Flexible Box Layout) es un modelo de maquetacion unidimensional de CSS disenado para distribuir espacio y alinear elementos dentro de un contenedor, incluso cuando su tamano es desconocido o dinamico. Es "unidimensional" porque trabaja con una sola direccion a la vez: fila (horizontal) o columna (vertical). Flexbox ha revolucionado la maquetacion web, reemplazando tecnicas antiguas basadas en floats y trucos de posicionamiento.

Para activar Flexbox, se aplica display: flex al contenedor padre. Los hijos directos de ese contenedor se convierten automaticamente en "flex items" y se pueden distribuir y alinear con propiedades especificas.

Propiedades del contenedor (flex container)

.contenedor {
    display: flex;

    /* Direccion del eje principal */
    flex-direction: row;           /* horizontal (por defecto) */
    flex-direction: column;        /* vertical */
    flex-direction: row-reverse;   /* horizontal invertido */

    /* Distribucion en el eje principal */
    justify-content: flex-start;   /* al inicio (defecto) */
    justify-content: center;       /* centrado */
    justify-content: flex-end;     /* al final */
    justify-content: space-between;/* espaciado entre elementos */
    justify-content: space-around; /* espaciado alrededor */
    justify-content: space-evenly; /* espaciado uniforme */

    /* Alineacion en el eje transversal */
    align-items: stretch;     /* estira al alto del contenedor (defecto) */
    align-items: center;      /* centrado verticalmente */
    align-items: flex-start;  /* arriba */
    align-items: flex-end;    /* abajo */

    /* Permitir que los elementos salten de linea */
    flex-wrap: wrap;          /* permite salto de linea */
    flex-wrap: nowrap;        /* sin salto (defecto) */

    /* Espacio entre elementos */
    gap: 15px;               /* espacio entre items */
}

Propiedades de los items (flex items)

.item {
    flex: 1;   /* el item crece para ocupar espacio disponible */
    /* flex: 1 es abreviatura de flex-grow:1 flex-shrink:1 flex-basis:0 */
}
.item-doble {
    flex: 2;   /* este item ocupa el doble de espacio que flex:1 */
}

Ejemplo practico: Barra de navegacion con Flexbox

<!-- HTML -->
<nav class="navbar">
    <div class="logo">Mi Sitio</div>
    <ul class="menu">
        <li><a href="#">Inicio</a></li>
        <li><a href="#">Servicios</a></li>
        <li><a href="#">Contacto</a></li>
    </ul>
</nav>

/* CSS */
.navbar {
    display: flex;
    justify-content: space-between;
    align-items: center;
    background: #2C3E50;
    padding: 10px 20px;
}
.menu {
    display: flex;
    list-style: none;
    gap: 20px;
}

Ejemplo practico: Centrar un elemento vertical y horizontalmente

.contenedor-centrado {
    display: flex;
    justify-content: center;   /* centra horizontalmente */
    align-items: center;       /* centra verticalmente */
    height: 100vh;             /* alto completo de la ventana */
}

Ejemplo practico: Layout de tarjetas

.cards {
    display: flex;
    flex-wrap: wrap;     /* las tarjetas saltan de linea */
    gap: 20px;
}
.card {
    flex: 1 1 300px;    /* crece, se encoge, minimo 300px */
    padding: 20px;
    border: 1px solid #ddd;
    border-radius: 8px;
}

2.11 CSS Grid

CSS Grid es un sistema de maquetacion bidimensional que permite organizar elementos en filas y columnas simultaneamente. A diferencia de Flexbox que trabaja en una sola dimension, Grid puede controlar ambas dimensiones al mismo tiempo, lo que lo hace ideal para layouts complejos de pagina completa.

Grid se activa con display: grid en el contenedor padre. Se definen las columnas con grid-template-columns y las filas con grid-template-rows. La unidad fr (fraccion) es especifica de Grid y representa una fraccion del espacio disponible.

.grid-container {
    display: grid;
    grid-template-columns: 1fr 2fr 1fr;   /* 3 columnas: 25% 50% 25% */
    grid-template-rows: auto auto;        /* 2 filas de alto automatico */
    gap: 20px;                              /* espacio entre celdas */
}

/* Columnas de ancho fijo y flexible combinados */
.layout {
    display: grid;
    grid-template-columns: 250px 1fr;     /* sidebar fijo + contenido flexible */
    gap: 20px;
}

/* Repetir columnas iguales */
.galeria {
    display: grid;
    grid-template-columns: repeat(3, 1fr); /* 3 columnas iguales */
    gap: 15px;
}

Posicionar items en el grid

/* Un item que ocupa 2 columnas */
.item-ancho {
    grid-column: 1 / 3;   /* desde linea 1 hasta linea 3 (ocupa 2 columnas) */
}

/* Un item que ocupa 2 filas */
.item-alto {
    grid-row: 1 / 3;      /* desde fila 1 hasta fila 3 */
}

Ejemplo: Layout completo de pagina con Grid

.pagina {
    display: grid;
    grid-template-columns: 200px 1fr;
    grid-template-rows: 60px 1fr 50px;
    min-height: 100vh;
    gap: 0;
}
.header  { grid-column: 1 / -1; }  /* ocupa todas las columnas */
.sidebar { grid-column: 1; }
.main    { grid-column: 2; }
.footer  { grid-column: 1 / -1; }  /* ocupa todas las columnas */
Flexbox vs. Grid: Usa Flexbox para layouts unidimensionales (una fila de botones, una barra de navegacion, centrar un elemento). Usa Grid para layouts bidimensionales (la estructura general de la pagina con header, sidebar, contenido y footer). Ambos pueden y deben combinarse: Grid para la estructura general, Flexbox para los componentes internos.

TEMA 3: Programacion del Lado del Servidor con PHP

3.1 Que es PHP

PHP (PHP: Hypertext Preprocessor) es un lenguaje de programacion de codigo abierto especialmente disenado para el desarrollo web del lado del servidor. Cuando un usuario solicita una pagina web que contiene codigo PHP, el servidor web (como Apache) procesa el codigo PHP, ejecuta las instrucciones, y envia al navegador del usuario unicamente el resultado en HTML. El usuario nunca ve el codigo PHP, solo el HTML generado.

El flujo de trabajo es el siguiente: (1) el navegador del usuario envia una solicitud HTTP al servidor; (2) el servidor identifica que el archivo solicitado contiene codigo PHP; (3) el interprete PHP ejecuta el codigo, que puede consultar bases de datos, procesar formularios, leer archivos, etc.; (4) PHP genera una salida en HTML; (5) el servidor envia ese HTML al navegador del usuario, que lo renderiza.

Ventajas de PHP: es gratuito y de codigo abierto; tiene una curva de aprendizaje moderada; cuenta con una enorme comunidad y documentacion; se integra facilmente con MySQL/MariaDB y otros sistemas de bases de datos; es multiplataforma (Windows, Linux, macOS); y el stack XAMPP (Apache + MySQL + PHP) facilita el desarrollo local.

Desventajas: no es el lenguaje mas rapido en ejecucion; su tipado debil puede llevar a errores sutiles; y la calidad del codigo puede variar mucho porque permite multiples paradigmas (procedural, orientado a objetos, funcional). Para el desarrollo se pueden utilizar editores como VS Code (ligero y extensible), NetBeans (IDE completo con soporte nativo para PHP), o PHPStorm (IDE profesional de pago).

3.2 Sintaxis Basica de PHP

El codigo PHP se escribe dentro de las etiquetas de apertura <?php y cierre ?>. Todo lo que esta fuera de estas etiquetas se trata como HTML normal. Esto permite mezclar HTML y PHP en el mismo archivo, aunque es una buena practica separar la logica del presentacion.

3.4 Cadenas en PHP

Las cadenas de texto (strings) son uno de los tipos de datos mas utilizados en PHP, especialmente en el desarrollo web donde se generan grandes cantidades de HTML dinamico. PHP ofrece un amplio conjunto de funciones para manipular cadenas, desde operaciones simples como obtener la longitud hasta transformaciones complejas como buscar y reemplazar patrones.

La concatenacion de cadenas en PHP se realiza con el operador punto (.), a diferencia de otros lenguajes que usan +. Las comillas dobles permiten interpolar variables dentro de la cadena, mientras que las comillas simples tratan todo como texto literal.

<?php
$texto = "  Hola Mundo PHP  ";

// Longitud de la cadena
echo strlen($texto);                 // 19 (incluye espacios)

// Convertir a minusculas / mayusculas
echo strtolower($texto);              // "  hola mundo php  "
echo strtoupper($texto);              // "  HOLA MUNDO PHP  "

// Extraer subcadena
echo substr($texto, 2, 4);           // "Hola" (desde posicion 2, 4 caracteres)

// Buscar posicion de subcadena
echo strpos($texto, "Mundo");        // 7 (posicion donde empieza)

// Reemplazar texto
echo str_replace("Mundo", "Web", $texto);  // "  Hola Web PHP  "

// Dividir cadena en arreglo
$partes = explode(" ", trim($texto));  // ["Hola", "Mundo", "PHP"]

// Unir arreglo en cadena
echo implode(", ", $partes);          // "Hola, Mundo, PHP"

// Eliminar espacios en blanco
echo trim($texto);                    // "Hola Mundo PHP" (sin espacios extremos)

// Primera letra de cada palabra en mayuscula
echo ucwords("hola mundo");           // "Hola Mundo"

// Invertir cadena
echo strrev("Hola");                  // "aloH"

// Concatenacion
$saludo = "Hola" . " " . "Mundo";    // "Hola Mundo"
$saludo .= "!";                       // "Hola Mundo!" (concatenar y asignar)
?>

3.5 Arreglos (Arrays)

Los arreglos son estructuras de datos que permiten almacenar multiples valores en una sola variable. En PHP existen dos tipos principales: los arreglos indexados, donde cada elemento tiene un indice numerico que comienza en 0, y los arreglos asociativos, donde cada elemento tiene una clave (key) de tipo string que le da nombre.

<?php
// Arreglo indexado
$colores = ["rojo", "verde", "azul"];
echo $colores[0];       // "rojo"
echo $colores[2];       // "azul"

// Arreglo asociativo
$estudiante = [
    "nombre"  => "Maria Lopez",
    "edad"    => 21,
    "carrera" => "Ingenieria de Sistemas"
];
echo $estudiante["nombre"];  // "Maria Lopez"

// Funciones utiles para arreglos
echo count($colores);             // 3 (numero de elementos)

array_push($colores, "amarillo"); // agrega al final
array_pop($colores);               // elimina y retorna el ultimo
array_shift($colores);             // elimina y retorna el primero

sort($colores);                    // ordena ascendentemente
rsort($colores);                   // ordena descendentemente

// Verificar si un valor existe
if (in_array("rojo", $colores)) {
    echo "Rojo esta en el arreglo";
}

// Buscar el indice de un valor
$pos = array_search("verde", $colores);  // retorna el indice o false

// Recorrer arreglo asociativo
foreach ($estudiante as $clave => $valor) {
    echo "$clave: $valor <br>";
}
?>

Los arreglos en PHP son extremadamente flexibles: pueden contener valores de diferentes tipos, pueden ser multidimensionales (arreglos de arreglos), y se puede iterar sobre ellos facilmente con foreach. Son la estructura de datos mas utilizada en PHP para manejar colecciones de informacion.

3.6 Funciones

Las funciones son bloques de codigo reutilizables que realizan una tarea especifica. Permiten organizar el codigo en unidades logicas, evitar la repeticion y facilitar el mantenimiento. Una funcion se define una vez y puede invocarse (llamarse) multiples veces desde cualquier parte del programa.

<?php
// Definir una funcion basica
function saludar($nombre) {
    return "Hola, $nombre!";
}

// Llamar a la funcion
echo saludar("Carlos");   // "Hola, Carlos!"

// Funcion con parametros por defecto
function calcular_iva($monto, $tasa = 0.13) {
    return $monto * $tasa;
}

echo calcular_iva(1000);        // 130 (usa tasa por defecto 0.13)
echo calcular_iva(1000, 0.16);  // 160 (usa tasa personalizada)

// Funcion que retorna un arreglo
function obtener_datos() {
    return [
        "nombre" => "Ana",
        "edad"   => 20
    ];
}

$datos = obtener_datos();
echo $datos["nombre"];   // "Ana"
?>

Include y Require

PHP permite incluir el contenido de un archivo dentro de otro mediante include y require. La diferencia clave es que require detiene la ejecucion del script con un error fatal si el archivo no se encuentra, mientras que include solo genera un warning y continua. Se recomienda usar require para archivos esenciales (como la conexion a la base de datos) e include para archivos opcionales.

<?php
// Incluir archivo de conexion (obligatorio)
require "conexion.php";

// Incluir un componente de interfaz (opcional)
include "header.php";

// require_once y include_once evitan incluir el mismo archivo dos veces
require_once "funciones.php";
?>

3.7 Formularios con PHP

Una de las tareas mas comunes en el desarrollo web con PHP es el procesamiento de datos enviados desde formularios HTML. Cuando un usuario completa un formulario y lo envia, el navegador transmite los datos al servidor, donde PHP los recibe a traves de las variables superglobales $_GET o $_POST, dependiendo del metodo del formulario.

La variable $_GET es un arreglo asociativo que contiene los datos enviados mediante el metodo GET (visibles en la URL). La variable $_POST contiene los datos enviados mediante POST (no visibles en la URL). En ambos casos, las claves del arreglo corresponden a los atributos name de los campos del formulario.

<!-- formulario.html -->
<form action="procesar.php" method="POST">
    <label>Nombre:</label>
    <input type="text" name="nombre" required>

    <label>Email:</label>
    <input type="email" name="email" required>

    <label>Mensaje:</label>
    <textarea name="mensaje"></textarea>

    <button type="submit">Enviar</button>
</form>
<!-- procesar.php -->
<?php
// Verificar que el formulario fue enviado por POST
if ($_SERVER["REQUEST_METHOD"] === "POST") {

    // Recibir y limpiar datos
    $nombre  = trim($_POST["nombre"]);
    $email   = trim($_POST["email"]);
    $mensaje = trim($_POST["mensaje"]);

    // Validacion basica
    if (empty($nombre) || empty($email)) {
        echo "Por favor complete todos los campos obligatorios.";
    } else {
        echo "Gracias, $nombre. Hemos recibido su mensaje.";
    }
}

// Redirigir a otra pagina
header("Location: exito.html");
exit();  // siempre usar exit despues de header Location
?>
Importante: La funcion header("Location: ...") debe llamarse ANTES de cualquier salida HTML (incluyendo espacios o saltos de linea antes de <?php). De lo contrario, PHP generara un error "headers already sent". Siempre use exit() despues de una redireccion para detener la ejecucion del script.

3.8 Programacion Orientada a Objetos (POO)

La Programacion Orientada a Objetos (POO) es un paradigma de programacion que organiza el codigo en torno a "objetos" que combinan datos (propiedades) y comportamientos (metodos). En lugar de tener funciones y variables dispersas, la POO agrupa todo lo relacionado con un concepto en una sola unidad llamada clase. Un objeto es una instancia concreta de una clase, asi como una casa es una instancia concreta de un plano arquitectonico.

PHP soporta POO desde PHP 5, y se ha convertido en el paradigma dominante en frameworks modernos como Laravel, Symfony y CodeIgniter.

<?php
class Estudiante {
    // Propiedades (atributos)
    public $nombre;
    public $carrera;
    private $nota;       // solo accesible dentro de la clase
    protected $codigo;   // accesible en la clase y sus hijas

    // Constructor: se ejecuta al crear el objeto
    public function __construct($nombre, $carrera, $nota) {
        $this->nombre  = $nombre;
        $this->carrera = $carrera;
        $this->nota    = $nota;
    }

    // Metodo publico
    public function presentarse() {
        return "Soy $this->nombre, estudio $this->carrera";
    }

    // Metodo para acceder a propiedad privada (getter)
    public function getNota() {
        return $this->nota;
    }

    // Metodo para modificar propiedad privada (setter)
    public function setNota($nota) {
        if ($nota >= 0 && $nota <= 100) {
            $this->nota = $nota;
        }
    }

    // Metodo que evalua el estado
    public function estaAprobado() {
        return $this->nota >= 51;
    }
}

// Crear objetos (instancias de la clase)
$est1 = new Estudiante("Ana Garcia", "Sistemas", 85);
$est2 = new Estudiante("Luis Rojas", "Derecho", 45);

// Usar los objetos
echo $est1->presentarse();     // "Soy Ana Garcia, estudio Sistemas"
echo $est1->nombre;           // "Ana Garcia" (public, accesible)
echo $est1->getNota();         // 85

if ($est2->estaAprobado()) {
    echo "Aprobado";
} else {
    echo "Reprobado";           // Se imprime esto (45 < 51)
}
?>

Visibilidad de propiedades y metodos

ModificadorAcceso
publicAccesible desde cualquier parte (dentro y fuera de la clase).
privateSolo accesible dentro de la propia clase. No se hereda directamente.
protectedAccesible dentro de la clase y en las clases que la heredan.

La palabra clave $this dentro de un metodo se refiere al objeto actual. Se usa para acceder a las propiedades y metodos del propio objeto. El operador -> permite acceder a propiedades y metodos de un objeto desde fuera (si son publicos) o desde dentro con $this.

3.9 Cookies

Las cookies son pequenos archivos de texto que el servidor web almacena en el navegador del usuario. Se utilizan para recordar informacion entre diferentes solicitudes HTTP, ya que el protocolo HTTP es "sin estado" (stateless): cada solicitud es independiente y el servidor no recuerda al usuario entre una solicitud y la siguiente.

Las cookies se almacenan en el navegador del cliente y se envian automaticamente al servidor en cada solicitud posterior al mismo dominio. Son utiles para guardar preferencias del usuario (idioma, tema), rastrear visitas, o mantener al usuario identificado entre sesiones.

Crear una cookie

<?php
// setcookie(nombre, valor, expiracion, ruta, dominio, seguro, httponly)

// Cookie que expira en 30 dias
setcookie("usuario", "Juan", time() + (30 * 24 * 60 * 60), "/");

// Cookie que expira al cerrar el navegador (sin tiempo de expiracion)
setcookie("sesion_temp", "abc123");

// Eliminar una cookie (poner tiempo de expiracion en el pasado)
setcookie("usuario", "", time() - 3600, "/");
?>

Leer una cookie

<?php
// Verificar que la cookie existe antes de leerla
if (isset($_COOKIE["usuario"])) {
    echo "Bienvenido de nuevo, " . $_COOKIE["usuario"];
} else {
    echo "Bienvenido, visitante nuevo";
}
?>

Ejemplo: Contador de visitas con cookies

<?php
if (isset($_COOKIE["visitas"])) {
    $visitas = $_COOKIE["visitas"] + 1;
} else {
    $visitas = 1;
}

// Actualizar la cookie (expira en 1 anio)
setcookie("visitas", $visitas, time() + (365 * 24 * 60 * 60), "/");

echo "Has visitado esta pagina $visitas veces.";
?>
Importante: Al igual que header(), la funcion setcookie() debe llamarse ANTES de cualquier salida HTML. Las cookies se envian como encabezados HTTP, y los encabezados deben ir antes del cuerpo de la respuesta.

3.10 Sesiones

Las sesiones en PHP permiten almacenar informacion del usuario en el servidor (no en el navegador como las cookies) a lo largo de multiples paginas. Cuando se inicia una sesion, PHP genera un identificador unico (session ID) que se almacena como cookie en el navegador. En cada solicitud posterior, el navegador envia este ID, y PHP lo usa para recuperar los datos almacenados en el servidor asociados a ese usuario.

Diferencias entre cookies y sesiones

CaracteristicaCookiesSesiones
AlmacenamientoEn el navegador del clienteEn el servidor
SeguridadMenor (el usuario puede modificarlas)Mayor (datos en el servidor)
CapacidadLimitada (~4KB por cookie)Limitada solo por el servidor
DuracionConfigurable (pueden persistir dias, meses)Hasta que se cierre el navegador o se destruya
Uso tipicoPreferencias, rastreoAutenticacion, carritos de compra

Uso basico de sesiones

<?php
// SIEMPRE debe ser la primera linea del script (antes de cualquier HTML)
session_start();

// Almacenar datos en la sesion
$_SESSION["usuario"] = "Juan Perez";
$_SESSION["rol"]     = "admin";
$_SESSION["logueado"] = true;

// Leer datos de la sesion (en otra pagina)
echo $_SESSION["usuario"];  // "Juan Perez"

// Verificar si una variable de sesion existe
if (isset($_SESSION["logueado"]) && $_SESSION["logueado"] === true) {
    echo "Usuario autenticado";
} else {
    header("Location: login.php");
    exit();
}

// Eliminar una variable de sesion especifica
unset($_SESSION["rol"]);

// Destruir toda la sesion (cerrar sesion / logout)
session_start();
$_SESSION = [];           // vaciar el arreglo de sesion
session_destroy();         // destruir la sesion en el servidor
header("Location: login.php");
exit();
?>

Almacenar objetos en sesiones con serialize/unserialize

Por defecto, PHP serializa automaticamente los datos de $_SESSION para almacenarlos. Sin embargo, cuando se almacenan objetos de clases personalizadas, es necesario que la definicion de la clase este disponible (mediante require) antes de llamar a session_start(), para que PHP pueda reconstruir el objeto correctamente.

<?php
// pagina1.php - Guardar un objeto en la sesion
require "Estudiante.php";  // la clase debe cargarse ANTES de session_start
session_start();

$est = new Estudiante("Ana", "Sistemas", 90);
$_SESSION["estudiante"] = serialize($est);

// pagina2.php - Recuperar el objeto de la sesion
require "Estudiante.php";
session_start();

$est = unserialize($_SESSION["estudiante"]);
echo $est->presentarse();   // Funciona correctamente
?>

3.11 Acceso a Base de Datos con MySQLi

La mayoria de las aplicaciones web dinamicas necesitan almacenar y recuperar datos de una base de datos. PHP se integra naturalmente con MySQL (y su fork MariaDB), que es el sistema de gestion de bases de datos relacional mas utilizado en la web. La extension MySQLi (MySQL improved) proporciona la interfaz para conectarse y ejecutar consultas SQL desde PHP.

Conexion a la base de datos

<?php
// conexion.php
$servidor = "localhost";
$usuario  = "root";
$clave    = "";           // en XAMPP, root no tiene contrasena por defecto
$bd       = "mi_base_datos";

// Crear conexion
$conexion = new mysqli($servidor, $usuario, $clave, $bd);

// Verificar conexion
if ($conexion->connect_error) {
    die("Error de conexion: " . $conexion->connect_error);
}

// Establecer charset UTF-8
$conexion->set_charset("utf8");
?>

Consultas SELECT (leer datos)

<?php
require "conexion.php";

$sql = "SELECT id, nombre, email FROM usuarios";
$resultado = $conexion->query($sql);

if ($resultado->num_rows > 0) {
    while ($fila = $resultado->fetch_assoc()) {
        echo "ID: " . $fila["id"] . " - Nombre: " . $fila["nombre"] . "<br>";
    }
} else {
    echo "No se encontraron registros.";
}

$conexion->close();
?>

Consultas INSERT (crear datos)

<?php
require "conexion.php";

$nombre = $_POST["nombre"];
$email  = $_POST["email"];
$clave  = sha1($_POST["clave"]);  // encriptar contrasena con SHA1

// FORMA SEGURA: Prepared statements (previene SQL injection)
$stmt = $conexion->prepare("INSERT INTO usuarios (nombre, email, clave) VALUES (?, ?, ?)");
$stmt->bind_param("sss", $nombre, $email, $clave);
// "sss" indica 3 parametros de tipo string. Tipos: s=string, i=integer, d=double

if ($stmt->execute()) {
    echo "Usuario registrado exitosamente.";
} else {
    echo "Error: " . $stmt->error;
}

$stmt->close();
$conexion->close();
?>

Consultas UPDATE (actualizar datos)

<?php
require "conexion.php";

$id     = $_POST["id"];
$nombre = $_POST["nombre"];
$email  = $_POST["email"];

$stmt = $conexion->prepare("UPDATE usuarios SET nombre = ?, email = ? WHERE id = ?");
$stmt->bind_param("ssi", $nombre, $email, $id);

if ($stmt->execute()) {
    echo "Usuario actualizado.";
    header("Location: listar.php");
    exit();
}

$stmt->close();
$conexion->close();
?>

Consultas DELETE (eliminar datos)

<?php
require "conexion.php";

$id = $_GET["id"];

$stmt = $conexion->prepare("DELETE FROM usuarios WHERE id = ?");
$stmt->bind_param("i", $id);
$stmt->execute();

header("Location: listar.php");
exit();
?>
Seguridad: NUNCA inserte datos del usuario directamente en las consultas SQL (por ejemplo: "SELECT * FROM usuarios WHERE id = " . $_GET["id"]). Esto es vulnerable a inyeccion SQL. Siempre use prepared statements con bind_param(). Para contrasenas, use sha1() como minimo, aunque password_hash() es mas seguro en aplicaciones reales.

3.12 Patron de Aplicacion Web Completa (CRUD)

Una aplicacion web tipica implementa las cuatro operaciones basicas sobre datos: Crear (Create), Leer (Read), Actualizar (Update) y Eliminar (Delete) — conocidas como CRUD. A continuacion se presenta la estructura tipica de una aplicacion PHP con base de datos, siguiendo un patron comun de archivos separados por responsabilidad.

Estructura de archivos tipica

mi-proyecto/
    conexion.php          // Conexion a la base de datos
    login.php             // Formulario de inicio de sesion
    autenticar.php        // Procesar login
    logout.php            // Cerrar sesion
    listar.php            // READ: Mostrar todos los registros
    formulario.php        // Formulario para crear nuevo registro
    crear.php             // CREATE: Procesar nuevo registro
    formulario-editar.php // Formulario de edicion pre-llenado
    actualizar.php        // UPDATE: Procesar actualizacion
    eliminar.php          // DELETE: Eliminar registro

Archivo conexion.php

<?php

TEMA 4: Programacion del Lado del Cliente con JavaScript

4.1 Que es JavaScript

JavaScript es un lenguaje de programacion interpretado, de tipado dinamico y multi-paradigma que se ejecuta principalmente en el navegador del usuario (lado del cliente). Permite crear paginas web interactivas, validar formularios sin contactar al servidor, manipular el contenido HTML/CSS de forma dinamica y comunicarse con APIs remotas.

Caracteristicas principales de JavaScript:

  • Interpretado: No requiere compilacion. El navegador lo ejecuta directamente.
  • Tipado dinamico: Las variables no tienen tipo fijo; el tipo se determina en tiempo de ejecucion.
  • Basado en prototipos: La herencia se logra mediante prototipos (aunque ES6 introduce la sintaxis class).
  • Multi-paradigma: Soporta programacion imperativa, orientada a objetos y funcional.
  • Ubicuo: Ejecuta en navegadores, servidores (Node.js), escritorio (Electron) y moviles (React Native).
Programacion del lado del cliente: El codigo JavaScript se descarga junto con el HTML y se ejecuta en el navegador del usuario. Esto permite respuestas instantaneas sin necesidad de contactar al servidor para cada interaccion, mejorando significativamente la experiencia del usuario.

4.2 Historia y ECMAScript

JavaScript fue creado por Brendan Eich en 1995 mientras trabajaba en Netscape. Originalmente se llamo Mocha, luego LiveScript, y finalmente JavaScript (por razones de marketing, no tiene relacion con Java). Fue estandarizado como ECMAScript (ECMA-262) para garantizar interoperabilidad entre navegadores.

TEMA 5: Aplicaciones de Internet Enriquecidas (RIA, AJAX, Fetch API)

5.1 Que es una RIA (Rich Internet Application)

Una RIA (Rich Internet Application) es una aplicacion web que ofrece la interactividad y experiencia de una aplicacion de escritorio, pero ejecutandose en el navegador. Combina lo mejor de ambos mundos: la riqueza visual de las apps de escritorio y la accesibilidad universal de la web.

Caracteristicas de una RIA:

  • Comunicacion asincrona: El navegador se comunica con el servidor sin recargar la pagina completa.
  • Actualizacion parcial: Solo se actualiza la parte de la pagina que cambio (DOM manipulation).
  • Procesamiento en el cliente: JavaScript maneja la logica de la interfaz.
  • Respuesta inmediata: El usuario percibe interactividad instantanea.
  • Interfaz rica: Drag & drop, animaciones, graficos en tiempo real.
Ejemplos actuales de RIA: Gmail, Google Docs, Trello, Figma, Spotify Web, VS Code Web, Notion. Todas se ejecutan completamente en el navegador, se comunican con servidores mediante Fetch API, y ofrecen experiencias comparables a aplicaciones nativas.

5.3 AJAX: concepto y funcionamiento

AJAX (Asynchronous JavaScript And XML) no es un lenguaje ni una tecnologia, sino un conjunto de tecnicas que permiten que las aplicaciones web se comuniquen con el servidor de forma asincrona, sin recargar la pagina. Hoy se usa JSON en lugar de XML.

Flujo de una peticion AJAX:

  1. El usuario realiza una accion (click, submit, escribir).
  2. JavaScript crea una peticion HTTP (Fetch API).
  3. La peticion se envia al servidor en segundo plano (el usuario puede seguir interactuando).
  4. El servidor procesa y responde con datos (generalmente JSON).
  5. JavaScript recibe la respuesta y actualiza solo la parte necesaria del DOM.

5.4 XMLHttpRequest (legado)

XMLHttpRequest fue la primera API para realizar peticiones asincronas. Aunque aun funciona, es verbosa y compleja. Se presenta aqui para entender codigo existente, pero no se recomienda para proyectos nuevos.

// XMLHttpRequest - forma clasica (NO recomendada)
const xhr = new XMLHttpRequest();

// 1. Configurar callback
xhr.onreadystatechange = function() {
  if (xhr.readyState === 4 && xhr.status === 200) {
    const data = JSON.parse(xhr.responseText);
    console.log(data);
  }
};

// 2. Abrir conexion (metodo, URL, asincrono)
xhr.open("GET", "api/usuarios.php", true);

// 3. Enviar peticion
xhr.send();

Estados de readyState: 0=UNSENT, 1=OPENED, 2=HEADERS_RECEIVED, 3=LOADING, 4=DONE (respuesta lista).

5.5 Fetch API: GET y POST (moderno)

La Fetch API es el reemplazo moderno de XMLHttpRequest. Usa Promesas nativas, es mas limpia y compatible con async/await.

GET: obtener datos

// GET simple
const response = await fetch("api/usuarios.php");
const usuarios = await response.json();

// GET con parametros
const params = new URLSearchParams({ buscar: "Carlos", pagina: 1 });
const resp = await fetch(`api/buscar.php?${params}`);
const resultados = await resp.json();

POST: enviar datos

// POST con JSON
const response = await fetch("api/usuario.php", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ nombre: "Carlos", email: "c@mail.com" })
});
const resultado = await response.json();
Importante: fetch() SOLO rechaza la Promise en errores de red (sin conexion, DNS). Errores HTTP (404, 500) NO causan rechazo. Siempre verificar response.ok antes de procesar la respuesta.

5.8 CORS (Cross-Origin Resource Sharing)

Por seguridad, los navegadores bloquean peticiones HTTP a dominios diferentes al de la pagina (Same-Origin Policy). CORS permite al servidor indicar que origenes externos tienen permiso para acceder a sus recursos.

<?php
// Al inicio del archivo PHP de la API
header("Access-Control-Allow-Origin: *");
header("Access-Control-Allow-Methods: GET, POST, PUT, DELETE");
header("Access-Control-Allow-Headers: Content-Type, Authorization");
header("Content-Type: application/json; charset=UTF-8");
?>
En produccion nunca usar * como origin. Especificar el dominio exacto: Access-Control-Allow-Origin: https://miapp.com

5.9 PHP como API REST

<?php
// api/usuarios.php - API REST con PHP
header("Content-Type: application/json; charset=UTF-8");
header("Access-Control-Allow-Origin: *");
require_once "conexion.php";

$method = $_SERVER["REQUEST_METHOD"];

switch ($method) {
  case "GET":
    $result = $con->query("SELECT * FROM usuarios");
    $usuarios = [];
    while ($f = $result->fetch_assoc()) $usuarios[] = $f;
    echo json_encode($usuarios);
    break;

  case "POST":
    $data = json_decode(file_get_contents("php://input"), true);
    $stmt = $con->prepare("INSERT INTO usuarios (nombre, email) VALUES (?, ?)");
    $stmt->bind_param("ss", $data["nombre"], $data["email"]);
    $stmt->execute();
    echo json_encode(["exito" => true, "id" => $con->insert_id]);
    break;

  case "DELETE":
    $id = $_GET["id"];
    $stmt = $con->prepare("DELETE FROM usuarios WHERE id = ?");
    $stmt->bind_param("i", $id);
    $stmt->execute();
    echo json_encode(["exito" => $stmt->affected_rows > 0]);
    break;
}
?>
Nota: Para recibir JSON enviado desde fetch() con Content-Type: application/json, PHP no puede usar $_POST. Se debe usar json_decode(file_get_contents("php://input"), true).

WebSocket establece una conexion bidireccional persistente entre cliente y servidor, ideal para comunicacion en tiempo real (chat, juegos, dashboards).

5.11 SPA, PWA y HTMX

Una SPA (Single Page Application) carga una sola pagina HTML y actualiza su contenido dinamicamente. La navegacion se maneja en el cliente sin recargar la pagina. Frameworks: React, Vue, Angular, Svelte.

Una PWA (Progressive Web App) es una app web instalable que funciona offline gracias a Service Workers y manifest.json. Requiere HTTPS.

HTMX es una alternativa ligera que agrega comportamiento AJAX directamente en atributos HTML, sin escribir JavaScript. Ideal para proyectos con PHP:

<!-- HTMX: AJAX sin JavaScript -->
<button hx-get="api/usuarios.php"
        hx-target="#resultado"
        hx-swap="innerHTML">
  Cargar Usuarios
</button>
<div id="resultado"></div>

<!-- Busqueda en tiempo real con HTMX -->
<input type="search"
       hx-get="api/buscar.php"
       hx-trigger="keyup changed delay:300ms"
       hx-target="#resultados"
       name="q">

5.12 Ejemplo: CRUD completo con Fetch + PHP

Frontend: cargar y mostrar datos

document.addEventListener("DOMContentLoaded", () => cargarUsuarios());

async function cargarUsuarios() {
  const tbody = document.querySelector("#tabla tbody");
  try {
    const resp = await fetch("api/usuarios.php");
    const usuarios = await resp.json();
    tbody.innerHTML = usuarios.map(u => `
      <tr>
        <td>${u.nombre}</td>
        <td>${u.email}</td>
        <td><button onclick="eliminar(${u.id})">Eliminar</button></td>
      </tr>`).join("");
  } catch (err) {
    tbody.innerHTML = "<tr><td colspan=3>Error al cargar</td></tr>";
  }
}

Frontend: crear y eliminar

async function crearUsuario(event) {
  event.preventDefault();
  const data = Object.fromEntries(new FormData(event.target));
  const resp = await fetch("api/usuarios.php", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data)
  });
  const result = await resp.json();
  if (result.exito) { event.target.reset(); cargarUsuarios(); }
}

async function eliminar(id) {
  if (!confirm("Eliminar?")) return;
  await fetch(`api/usuarios.php?id=${id}`, { method: "DELETE" });
  cargarUsuarios();
}
Este patron CRUD con Fetch + PHP API REST es la base de todas las aplicaciones web modernas. El frontend se comunica con el backend exclusivamente mediante JSON, permitiendo separar completamente la presentacion de la logica del servidor.

TEMA 6: Diseno Responsivo y Bootstrap

6.1 Por que Diseno Responsivo

En 2025, mas del 60% del trafico web proviene de dispositivos moviles. Esto significa que la mayoria de los usuarios acceden a los sitios web desde smartphones con pantallas de 360-430px de ancho, no desde monitores de escritorio.

El diseno responsivo (Responsive Web Design) es una tecnica que permite que un unico sitio web se adapte automaticamente a cualquier tamano de pantalla: moviles, tablets, laptops y monitores de escritorio. En lugar de crear versiones separadas del sitio para cada dispositivo, se usa CSS para reorganizar, redimensionar y ocultar/mostrar elementos segun el espacio disponible.

Por que es esencial

  • Google exige sitios responsivos para buen posicionamiento (SEO). Los sitios no responsivos son penalizados en resultados de busqueda.
  • Experiencia de usuario: los usuarios abandonan sitios que no se ven bien en su dispositivo.
  • Mantenimiento: un solo codigo base en vez de multiples versiones.
  • Accesibilidad: funciona en cualquier dispositivo presente y futuro.

6.2 Viewport y Meta Tag

El viewport es el area visible de la pagina web en el dispositivo. Sin configuracion especial, los navegadores moviles renderizan las paginas como si fueran un monitor de escritorio de ~980px y luego las miniaturizan, haciendo el contenido ilegible.

Para que el diseno responsivo funcione, es obligatorio incluir la siguiente meta tag en el <head> de todo documento HTML:

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">
  • width=device-width: el ancho de la pagina es igual al ancho real del dispositivo.
  • initial-scale=1.0: zoom inicial al 100% (sin zoom).

Sin esta linea, NADA de CSS responsivo funcionara correctamente en moviles.

6.3 Media Queries CSS

Las media queries son la herramienta fundamental de CSS para aplicar estilos diferentes segun las caracteristicas del dispositivo, principalmente el ancho de la pantalla.

/* Estilos base (para todos los tamanos) */
.contenedor {
  width: 100%;
  padding: 1rem;
}

/* Solo pantallas >= 768px (tablet y superior) */
@media (min-width: 768px) {
  .contenedor {
    width: 750px;
    margin: 0 auto;
  }
}

/* Solo pantallas >= 1200px (desktop) */
@media (min-width: 1200px) {
  .contenedor {
    width: 1140px;
  }
}

6.4 Mobile-First vs Desktop-First

Hay dos enfoques para escribir CSS responsivo:

Mobile-First (recomendado)

Se escriben los estilos base para movil y se usan min-width para agregar complejidad en pantallas mas grandes. Es el enfoque que usa Bootstrap.

/* Base: movil */
.nav { display: block; }

/* Tablet y superior */
@media (min-width: 768px) {
  .nav { display: flex; }
}

Desktop-First

Se escriben estilos para desktop y se usa max-width para adaptar a movil. Genera mas codigo y es menos eficiente.

Para crear layouts fluidos, debemos evitar unidades fijas (px) en layouts y usar unidades relativas:

6.6 Imagenes y Tipografia Responsiva

Imagenes responsivas

La regla basica para que las imagenes se adapten al contenedor:

img {
  max-width: 100%;
  height: auto;
}

Para imagenes que deben llenar un contenedor manteniendo su proporcion, se usa object-fit:

.cover {
  width: 100%;
  height: 300px;
  object-fit: cover; /* recorta sin deformar */
}

El elemento <picture> de HTML5 permite cargar imagenes diferentes segun el tamano de pantalla (mas pequenas para movil, mas grandes para desktop), ahorrando ancho de banda.

Tipografia responsiva con clamp()

h1 { font-size: clamp(1.5rem, 4vw, 3rem); }
p  { font-size: clamp(0.9rem, 1.5vw, 1.1rem); }

6.7 Bootstrap 5

Bootstrap es el framework CSS mas popular del mundo. Fue creado originalmente en Twitter (2011) por Mark Otto y Jacob Thornton. Proporciona componentes HTML, CSS y JavaScript predefinidos para crear sitios web responsivos rapidamente.

Configuracion con CDN

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <!-- Bootstrap CSS -->
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css"
    rel="stylesheet">
  <title>Mi sitio</title>

<body>
  <div class="container">

  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>

Se necesitan 3 elementos esenciales: la meta viewport, el CSS de Bootstrap (en el head) y el JS de Bootstrap (antes de cerrar body).

6.8 Sistema de Grillas (Grid System)

Bootstrap usa un sistema de grillas de 12 columnas basado en Flexbox. Tres elementos fundamentales:

  • .container: contenedor con ancho fijo que cambia en cada breakpoint. .container-fluid = 100% siempre.
  • .row: fila que agrupa columnas. Agrega gutters (espaciado) entre ellas.
  • .col-*: columnas de 1 a 12. La suma de columnas en una fila debe ser 12 (o menos).
<div class="container">
  <div class="row">
    <div class="col-12 col-md-6 col-lg-4">A</div>
    <div class="col-12 col-md-6 col-lg-4">B</div>
    <div class="col-12 col-md-6 col-lg-4">C</div>
  </div>
</div>

Este ejemplo muestra 1 columna en movil (col-12), 2 columnas en tablet (col-md-6) y 3 columnas en desktop (col-lg-4).

6.12 Buenas Practicas de Diseno Responsivo

  1. Mobile-first siempre: disenar primero para movil y agregar complejidad para pantallas grandes.
  2. Viewport meta obligatorio: sin el meta tag viewport, nada funciona en moviles.
  3. No usar px fijos en layouts: usar %, vw, rem, clamp(), min(), max().
  4. Imagenes responsivas: max-width: 100%; height: auto; en todas las imagenes.
  5. Contenido legible sin zoom: font-size minimo 16px en movil, botones tocables de al menos 44x44px.
  6. Probar en dispositivos reales: los emuladores no capturan todo (velocidad de red, tamano real del dedo).
  7. Probar en al menos 3 tamanos: movil (375px), tablet (768px) y desktop (1440px).
  8. Usar DevTools: F12 > Toggle Device Toolbar (Ctrl+Shift+M) para simular cualquier dispositivo.
El diseno responsivo no es opcional, es un requisito. Mas del 60% de los usuarios navegan desde el movil, y Google penaliza los sitios que no se adaptan a pantallas pequenas. Dominar media queries, Bootstrap o Tailwind es esencial para cualquier desarrollador web moderno.
